    Complete Dijkstra Deadlock Avoidance Engine: 1. State Safety Algorithm + 2. Dynamic Resource-Request Avoidance Algorithm (Requesti)

    🛡️ Part 2: Deadlock Avoidance — Dynamic Resource-Request Algorithm (Requesti)

    When a process Pi requests additional resources at runtime, the OS runs the 3-Step Banker's Avoidance Test before granting them. If granting the request would put the OS into an UNSAFE state, the OS avoids deadlock by denying & rolling back the provisional allocation!

    ⚡ One-Click Textbook Scenarios:

    📋 Step-by-Step Safety Proof

    At each step: find a process whose Need ≤ Work. Let it finish, add its Allocation back to Work.

    Step Process Need Work (Before) Need ≤ Work? Releases Work (After)

    📖 Full Explanation

    🧮 BANKER'S DEADLOCK AVOIDANCE — FORMULA REFERENCE
    Part 1 — Safety Algorithm:
      Need[i][j] = Max[i][j] − Allocation[i][j]
      Safety Check = Need[i] ≤ Work (for all resource types j)
      On finish: Work := Work + Allocation[i], Finish[i] := True
    Part 2 — Resource-Request Avoidance Algorithm (Process Pi requests Requesti):
      Step 1: Check Requesti ≤ Needi      (Else error: exceeded maximum claim)
      Step 2: Check Requesti ≤ Available  (Else Pi must wait for resources)
      Step 3: Provisional Allocation: Available −= Requesti; Allocationi += Requesti; Needi −= Requesti
              → If Safety Algorithm returns SAFE: Grant request! Else: DENY & ROLLBACK (Deadlock Avoided!)

     DBMS Viva & Exam Highlights: Heuristic Query Optimization
    
                        
    
                            
    
                                1. Why push selections (σ) down?
    
                                In naive plans, Cartesian products or full joins produce $M \times N$ tuples. Filtering before the join reduces the cardinalities to $M' \ll M$ and $N' \ll N$, slashing disk I/O exponentially.
                            
    
                            
    
                                2. Why push projections (π) down?
    
                                Discarding unused attributes before joining narrows the tuple byte-width, enabling dramatically more records to fit in each RAM buffer pool page.
                            
    
                            
    
                                3. Cost-Based vs. Heuristic:
    
                                Heuristics apply universal equivalence rules regardless of row counts. Modern CBO (Cost-Based Optimizers like MySQL/Oracle) combine heuristics with catalog statistics (histograms) to estimate total I/O cost.
